# PRD：公交客流智能问答助手

| 项目 | 内容 |
|---|---|
| 版本 | v1.0 |
| 角色 | 产品经理 |
| 状态 | 原型验证 |

## 1. 问题与机会

公交客流分析涉及大量领域知识（数据结构、指标定义、清洗规则、可视化方法）。业务人员在使用分析工具时，常遇到三类问题：

1. **查找成本高**：知识点分散在多份文档中，关键词搜索难以命中自然语言提问。
2. **缺乏依据**：直接问大模型容易得到似是而非的答案，无法验证来源。
3. **幻觉风险**：模型会编造资料中不存在的数字和结论，在数据分析场景不可接受。

## 2. 目标用户

- **主要用户**：公交数据分析师、交通规划研究人员
- **核心场景**：快速查询领域知识、确认指标定义、了解分析方法

## 3. 产品目标

| 目标 | 衡量指标 | 目标值 |
|---|---|---|
| 准确回答知识库内问题 | 答案要点准确率 | ≥ 80% |
| 找到正确依据 | 检索命中率 Recall@3 | ≥ 90% |
| 不编造答案 | 拒答准确率 | ≥ 90% |
| 响应及时 | 平均响应时间 | ≤ 3 秒 |

## 4. 用户故事

- 作为数据分析师，我想用自然语言提问字段含义，以便快速理解数据。
- 作为研究人员，我希望每个结论都有来源标注，以便在报告中引用。
- 作为业务人员，我希望知识库外的问题能明确告知，避免被误导。

## 5. 功能范围

### v1.0（已实现）
- 领域文档加载与切分
- BM25 检索 + 带引用生成
- 幻觉防护（明确拒答）
- 评测脚本与报告

### 后续版本
- 向量检索 + Rerank 重排序
- Text2SQL：从知识问答扩展到真实数据查询
- Web 界面 + 对话历史

## 6. 关键设计决策

**决策 1：检索与生成分离评估。** 答案错误时，先判断是检索没召回还是生成没遵循资料，避免"效果好坏"笼统归因，指导优化方向。

**决策 2：无 Key 时降级为抽取式生成。** 保证项目零依赖可运行，降低演示与评审门槛，同时保留接入大模型的扩展点。

**决策 3：明确拒答优先于"尽量回答"。** 在数据分析场景，编造答案的代价远高于拒答，因此 Prompt 中强约束"无依据即拒答"。

## 7. 风险与限制

- BM25 基于关键词匹配，对同义改写和语义相近但字面不同的问题召回能力有限。
- 关键词覆盖率是准确率的近似评估，与人工语义判断存在偏差。
- 知识库为示例文档，未接入真实客流数据，不支持数值型问题。
