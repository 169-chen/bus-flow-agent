# 项目上传与简历填写指南

## 一、上传到哪里

| 平台 | 用途 | 建议 |
|---|---|---|
| **GitHub** | 主作品集，简历放这个链接 | 首选。技术招聘认可度最高 |
| **Gitee** | 国内访问快的镜像 | 备选。国内 HR 打不开 GitHub 时用它 |

两边都放，简历只写 GitHub 链接（面试时若对方打不开，再给 Gitee）。

## 二、上传步骤

### GitHub（主）

1. 注册/登录 github.com，点右上角 `+` → `New repository`
2. 仓库名填 `bus-flow-agent`，选 **Public**，不要勾选 Initialize with README
3. 创建后，在本项目目录执行：

```bash
git remote add origin https://github.com/你的用户名/bus-flow-agent.git
git branch -M main
git push -u origin main
```

### Gitee（镜像，可选）

1. 登录 gitee.com，新建仓库，名字同样 `bus-flow-agent`，设为公开
2. 执行：

```bash
git remote add gitee https://gitee.com/你的用户名/bus-flow-agent.git
git push gitee main
```

以后两个平台都更新时：`git push origin main && git push gitee main`

## 三、简历怎么写

### 项目名
公交客流智能问答助手｜AI 产品经理项目

### 项目描述（可直接用）

> **背景**：面向公交客流分析场景，解决领域知识分散、通用大模型回答无依据的问题。
> **职责**：独立完成产品设计与原型开发，负责需求定义、知识库构建、评测体系设计与效果优化。
> **工作**：
> - 设计并实现 RAG 问答原型：完成领域文档切分、BM25 检索、带引用生成，对知识库外问题实现明确拒答；
> - 设计 50 题四层评测集（事实问答/指标理解/方法应用/拒答），建立"检索命中率 + 答案准确率 + 拒答准确率"分层评估体系；
> - 通过评测发现 BM25 强行召回导致幻觉的问题，经三轮归因与规则优化，将拒答准确率从 0% 提升至 100%；
> - 输出 PRD、竞品分析与评测报告，明确关键设计决策与优化方向。
> **成果**：检索命中率 80%，拒答准确率 100%，形成完整的"评测-归因-优化-复测"闭环。

### 面试怎么讲（准备这三个问题）

1. **"为什么用 BM25 不用向量检索？"**
   → 项目定位是零依赖可运行的原型验证，BM25 纯 Python 实现便于演示；向量检索是明确的优化方向，已在 README 中列出。

2. **"评测发现什么问题，怎么解决的？"**
   → 讲三轮优化故事（见 README 评测结果章节），重点说清"为什么关键词覆盖率会误伤专业术语"这个归因过程。

3. **"这个产品你怎么判断该不该上 AI？"**
   → 引用竞品分析：知识分散+需溯源+幻觉不可接受，才适合 RAG；简单查询用关键词搜索即可，不必上 AI。

## 四、注意事项

- 简历链接写完整 URL：`https://github.com/你的用户名/bus-flow-agent`
- 提交前确认 `.env` 未被上传（已在 .gitignore 中排除）
- 仓库 README 是门面，HR 主要看它——本项目 README 已包含项目背景、技术方案、评测结果
- 数据文件（2.6GB 的公交数据）不要上传，超过 GitHub 单文件 100MB 限制，且涉及数据合规
