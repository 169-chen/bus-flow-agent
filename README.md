# 公交客流智能问答助手

> 一个面向**城市公交客流分析场景**的 RAG 知识库问答系统。用户用自然语言提问，系统基于公交 IC 卡数据领域知识库检索并生成带引用的回答。

## 项目背景

公交客流分析涉及 IC 卡数据结构、时空特征指标、数据清洗规则、可视化方法等多维度知识。业务人员查询这些知识时，传统关键词搜索难以理解自然语言问题，且无法给出来源依据。本项目将领域文档构建为知识库，通过 RAG（检索增强生成）实现可追溯的智能问答。

## 核心功能

- **领域知识库问答**：支持"数据包含哪些字段""如何识别异常值"等自然语言提问
- **带引用回答**：每个结论标注来源文档，可追溯、可验证
- **幻觉防护**：对知识库外的问题明确拒答，不编造数字和结论
- **完整评测体系**：50 题测试集，从检索和生成两层分离评估效果

## 技术方案

| 模块 | 实现 | 说明 |
|---|---|---|
| 文档处理 | `src/loader.py` | 按段落 + 字符滑窗切分，保留来源标记 |
| 检索 | `src/retriever.py` | 纯 Python BM25，中文单字 + 二元组分词，零第三方依赖 |
| 生成 | `src/generator.py` | 有 API Key 走大模型；无 Key 自动降级为抽取式生成 |
| 评测 | `evaluation/run_eval.py` | Recall@K、答案准确率、拒答准确率、错误归因 |

**为什么用 BM25 而不是向量检索？** 项目定位是可零依赖运行的原型验证：BM25 纯 Python 实现，无需下载模型或安装依赖，便于演示和迁移。接入向量库（FAISS/Chroma）是明确的后续优化方向。

## 快速开始

```bash
# 1. 运行问答演示（零依赖）
python app.py

# 2. 运行评测并生成报告
python evaluation/run_eval.py

# 3.（可选）接入真实大模型
cp .env.example .env
# 编辑 .env 填入 LLM_API_KEY，再运行 python app.py
```

示例提问：
- `公交IC卡数据包含哪些核心字段？`
- `数据清洗包含哪些规则？`
- `明天各站点的客流预测值是多少？` ← 应正确拒答

## 评测结果

运行 `python evaluation/run_eval.py` 后，报告输出到 `evaluation/reports/eval_report.md`。

当前基线（抽取式生成，无 API Key）：

| 指标 | 数值 |
|---|---|
| 检索命中率 Recall@3 | 80% |
| 答案要点准确率 | 32% |
| 拒答准确率 | 100% |

**评测驱动优化的真实记录**（面试可讲）：

1. 首轮评测发现拒答准确率仅 0%——BM25 对知识库外问题仍强行召回文档，导致硬凑答案（幻觉）。
2. 用关键词覆盖率修复，拒答升至 100%，但正常题被误伤，准确率跌至 15%——说明规则过严。
3. 分析误判样例发现，专业术语（"箱线图""下钻"）被覆盖率算法误判为越界。
4. 改为"越界信号词 + 检索得分"双规则：命中金额/预测/机构等信号词直接拒答，无信号时看检索得分。
5. 最终：拒答 100%，准确率恢复至 32%。剩余错误集中在抽取式生成对多关键词问题的覆盖不足，接入大模型后可改善。

这个"发现问题 → 归因 → 优化 → 复测"的闭环，正是 AI 产品经理需要的核心能力。

## 项目结构

```
bus-flow-agent/
├── app.py                     # 交互式演示入口
├── src/
│   ├── config.py              # 配置（路径、检索参数、API）
│   ├── loader.py              # 文档加载与切分
│   ├── retriever.py           # BM25 检索器
│   ├── generator.py           # 生成（大模型 + 抽取式兜底）
│   └── pipeline.py            # RAG 管线串联
├── data/knowledge/            # 领域知识库文档
├── evaluation/
│   ├── testset.json           # 50 题测试集（4 类）
│   ├── run_eval.py            # 评测脚本
│   └── reports/               # 评测报告输出
└── docs/
    ├── PRD.md                 # 产品需求文档
    └── 竞品分析.md            # 竞品分析
```

## 可优化方向

1. 接入向量检索（FAISS / Chroma）与 Embedding 模型，提升语义召回
2. 引入 Rerank 模型对召回结果重排序
3. 用 LLM-as-Judge 替代关键词匹配，提升评测的语义准确性
4. 接入真实公交客流数据，从"知识问答"扩展到"数据问答"（Text2SQL）
